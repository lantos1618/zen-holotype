# rt-scoped-runtime — judge panel ruling (2026-07)

Aggregate 5.9/10, revise-then-build.

## Aggregate score (5.9/10)

Mean **5.875**, range **5.5–6.0**. This is a tight cluster, and the tightness is itself the signal: four judges wearing very different lenses (region calculus, shipped-Zig pragmatism, DX, Pony/actor semantics) independently landed within half a point. That is not four people hedging toward the middle — it is convergence. They agree the design is *novel and coherent at its core* (colorless actors, scoped-region safety, build.zen root capability) and they agree it *rests on a headline claim that is false as stated*. The half-point spread comes entirely from one axis: how bad is metastasis. The Zig pragmatist scores it a "livable 6" because he reads rt-everywhere as **signal** (the whole point of the language killing hidden await); the Pony judge drags it to 5.5 because on top of metastasis the example has an actual liveness bug and a cross-actor UAF. No judge scored it above 6, and two independently found *fatal* soundness holes — so the honest read is "promising design, one true thesis, several load-bearing lies," not "nearly shippable."

## The explicit-vs-ambient ruling

**Tally: hybrid-needed ×3 (PL-theory, DX, Pony), explicit-is-right ×1 (Zig).** And the "explicit" vote is softer than its label — that judge's actual position is "explicit beats *ambient*, but split the bundle and infer/thread only the alloc cap," which is a hybrid in everything but name. So the real tally is **4/4 against "explicit rt on every allocating function."**

**THE answer: hybrid. Ambient *within* an rt-scope (the actor's synchronous call tree, or a lexical `runtime{…}` region); explicit *only* at boundaries — scope introduction, `spawn`, and policy/test swaps.**

Does rt metastasize into every signature? **Yes — unanimously, and it is not close.** All four judges independently walked the same argument: any function that builds a Vec/Map/string, parses into owned data, formats, or concatenates *transitively allocates*, so the "provably cannot allocate" set is just leaf arithmetic and in-place mutation — a minority. rt therefore lands on ~80% of non-leaf signatures, which is *exactly* Zig's lived `allocator:`-everywhere reality — the thing this design claims to beat. An effect marker present on four of five functions is Haskell's ubiquitous `IO`: technically true, informationally dead.

What saves it? Not per-signature threading — that reproduces the noise. Three things, in order:
1. **Move the ambient boundary from the function to the scope.** "No rt ⇒ no heap" becomes a *scope-level* property enforced by the existing escape/UAF checker (a container may not outlive its rt-region), not a per-call tax. Leaf code inside a scope is undecorated; the effect is still visible — it lives at the `runtime{…}` header and at `spawn`, where you actually make the policy decision.
2. **The design already concedes this.** Clause 4 makes rt *ambient in actors* (`self` carries it, behaviors take no rt) while free functions thread it explicitly. That is two mental models for one capability — proof the ambient-within-a-boundary form is the natural one; generalize it, don't special-case it.
3. **Reject pure Odin ambient.** The Zig judge is right that dynamic-scoped `context.allocator` re-hides the very effect the language spent its identity deleting, and kills test-time injection. So: ambient *within a statically-known lexical/actor region*, explicit at the region edge. That keeps object-capability auditability (rt is an unforgeable lexical value, strictly better than Odin's spooky dynamic scope and Rust's global) while paying the plumbing only once per scope instead of once per function.

Decisive: **not explicit-per-function, not Odin-ambient — ambient-within-scope, explicit-at-boundary.**

## Top holes (ranked, with severity + fix)

1. **[FATAL] The per-actor memory model fights the message model → cross-actor UAF.** (PL-theory + Pony fatal, DX major.) Default gc = per-actor bump arena; move-on-send transfers a block that lives in *sender A's* arena; A's arena bulk-frees independently of B's need → dangling pointer. The design's *own flagship example* does this: `rt.spawn(Counter(seen: rt.vec<i32>()))` allocates `seen` in **main's** arena, then hands it to an actor with its own heap. Pony only survives this because ALL objects live in one ORCA-tracked object space. **Fix: sendable/actor-state allocation must come from a shareable, ORCA/ARC-tracked heap — never the per-actor bump arena. Actor state is constructed *under the actor's own collector* (construct-in-actor), not the spawner's. Bump-arena rt is for actor-local scratch only.**

2. **[FATAL] The headline "rt presence = allocation effect" is unsound.** (All four; PL + Pony call it fatal.) It is defeated three independent ways: (a) closures capture rt — `(cb: () -> Vec<i32>)` allocates with no rt param and the bare arrow carries no latent effect; (b) `self` carries rt, so a method with no rt param allocates; (c) rt bundles alloc+sched+gc, so "rt present" means "touches runtime," not "allocates." **Fix: drop the effect *biconditional*. Reframe rt as a scoped *capability*, not an allocation effect. If you want allocation-as-effect at all, put the effect on the arrow type (Koka-style latent effect) — otherwise stop claiming the contrapositive.**

3. **[FATAL/MAJOR] "Escape-checker gives Pony isolation for free" conflates region-lifetime with uniqueness.** (PL fatal, Zig major, Pony implicit.) Escape analysis is *temporal* (don't outlive the scope); Pony `iso` is *spatial* (no aliases). Escape analysis **never** establishes uniqueness. On the N-core work-stealing scheduler, sending an rt-captured Vec while keeping an alias is a real data race. **Fix: sends need a reference-capability layer (at minimum iso/val) or deep-copy-into-recipient / provably-immutable payloads. Stop claiming isolation from a lifetime pass — and note the move/escape-for-sends checker is a *separate, still-partial* pass per your own memory notes.**

4. **[MAJOR] rt bundles three non-splittable effects → over-granting + lost granularity.** (All four.) A pure arena-bump leaf is force-fed spawn + gc authority (least-privilege violation, ironic for a "capability"), and you can't read "spawns concurrency" vs "bumps a pointer" off the signature. **Fix: make alloc/sched/gc independently passable; a function requests only the cap it uses. Bundle into `rt` only as ergonomic sugar where all three are genuinely used.**

5. **[MAJOR] alloc and gc are not orthogonal — the 3-axis matrix has illegal cells.** (PL + Zig.) `runtime(alloc: Scratch, gc: ARC)` is incoherent: bulk-freeing a region vs refcounting per object are contradictory. **Fix: constrained combinators that reject incompatible (alloc, gc) pairs at build time; region-alloc implies no per-object gc.**

6. **[MAJOR] Receiver-slot theft breaks domain UFCS.** (Zig + DX.) Making rt the receiver so `rt.render_rows(cfg)` chains clean steals the UFCS slot from the domain noun — you lose `cfg.render_rows()` and `iter.filter().map().collect()` (collect allocates → rt must re-enter as an arg, breaking the chain). And a struct method that has `self` *and* allocates writes `self.foo(rt,…)` — now rt is the *second* param, so "effect lives in the receiver slot" isn't even stable across free-fn vs method. **Fix: don't force rt into the receiver slot; keep the domain type as receiver and access rt as scope-ambient.**

7. **[MAJOR] Managed containers adopt the side of the debate Zig deprecated.** (Zig.) `rt.vec<T>()` storing the handle so `v.push` takes no rt is Zig's old managed `ArrayList`; Zig moved to `ArrayListUnmanaged` as default (fat-struct tax per container, footgun when stored handle diverges from context, redundant). **Fix: unmanaged containers OR — better with the hybrid — scope-ambient literals that allocate in the current region.**

8. **[MAJOR] Reply/liveness unsolved; the flagship example dodges it.** (Pony.) `.Report` makes the actor print itself because `main` has no mailbox to receive a reply; deleting all await-shaped constructs overshoots Pony (which ships `Promise[A].next()`). And `main` returns 0 with **no `rt.run()`/quiescence join** — the program may exit before `.Inc` is processed. **Fix: add a colorless message-fulfilled `Promise`/`ReplyRef` (resolved by a delivered message, not a blocking get); make `main` a root actor / `rt.run()` join so replies land and the program reaches quiescence.**

9. **[MAJOR] Return-value region ownership is unsolved and re-forces threading.** (PL + Zig.) `render_rows … Vec<i32>` is region-erased; a Vec built in a nested `Scratch` scope and pushed into an outer Arena-lived list embeds a pointer into freed memory, and a pointer-keyed escape pass can miss a pointer inside a moved-by-value struct. **Fix: region/lifetime params on containers (accept it becomes Rust-like, not free) OR containers non-returnable across scope without explicit copy-into-outer-rt.**

10. **[MAJOR] ORCA is oversold; monomorphization blowup.** (Pony.) "Rc + color word + trace.zen" is a single-heap tracing collector, not ORCA (which is cross-actor deferred cycle detection with GC-increment/decrement *messages* and causal ordering). Separately, `rt: Rt<A,S,G>` threaded everywhere is whole-program 3-param generic inference on a frontend your own notes say **cannot yet infer `Vec<T>`**. **Fix: honestly downgrade to "per-actor RC/Arc + optional single-heap tracing" or spec the real protocol; erase rt to a vtable at boundaries by default, monomorphize only hot leaf paths.**

## Strongest parts (definitely keep)

- **Colorless by construction** — run-to-completion behaviors that never await mid-body mean coloring is *impossible*, not hidden. Every judge flagged this as the one part that is genuinely Pony, not cosplay. Removing checkpoint/coroutine hidden-await is correct and on-thesis.
- **rt as an explicit, unforgeable, lexically-scoped *value*** — the object-capability discipline is the design's real contribution: strictly more auditable than Odin/Jai dynamic `context` and Rust's global allocator.
- **build.zen root-scope + `main(rt: Rt)`** — declaring the root capability in the manifest and delivering it to main makes capability *provenance* explicit and swappable (Arena for prod, failing-alloc for tests, Inline sched for determinism) without touching call sites. Genuinely better than Zig, which has no declared root.
- **Collapsing SyncArena/AsyncArena into pluggable axes** — a real simplification of the monolithic Runtime trait, motivated by actual product-explosion in `runtime.zen`; generalizing the Allocator-trait pattern to sched/gc is one coherent idea.
- **Reusing the existing move/escape/UAF checker as the sendability substrate** — data-race-free sends without a runtime barrier, on machinery already built. Real leverage (just don't oversell what it proves — see hole 3).
- **Per-actor memory policy** — reclamation as an actor-local choice, not a global `--mm` flag, is the correct Pony instinct (the *mechanism* needs fixing, see hole 1, but the *locus* is right).
- **I/O completions as messages** — sound, actor-consistent, no hidden await.

## Verdict: **revise-then-build**

The core is novel, on-thesis, and worth building — but two independent *fatal* soundness holes (cross-actor UAF, unsound effect marker) mean writing code now ships a crash and a false guarantee. This is not a rethink (the colorless + scoped-capability + build.zen spine is sound); it is a design with one true thesis and three load-bearing overclaims that must be retracted or repaired first.

**The single most important change before any code: split allocation into two distinct lifetimes and make that the organizing principle — (1) actor-local *scratch* (region/bump, ambient-within-scope, statically forbidden to escape) and (2) *shareable/sendable* heap (ORCA- or ARC-tracked, the only thing a message payload or actor state may live in).** Every fatal and most majors are the same disease — conflating "cheap bulk-freed local memory" with "memory that crosses an actor boundary": the flagship UAF (hole 1), the escape≠isolation overclaim (hole 3), the alloc/gc matrix incoherence (hole 5), and the return-ownership problem (hole 9) all dissolve once these two are separate types with separate rules. Make that split first; it simultaneously forces the honest reframing of rt from "allocation effect" to "scoped capability" and gives the ambient-within-scope / explicit-at-boundary model its natural boundary.
